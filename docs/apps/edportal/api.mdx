Базовый адрес: **`/api/v1/agent`**. Версия HTTP `v1` не меняется. Вызовы REST Битрикс24 этот адрес не заменяют: внешняя система ходит сюда напрямую.

Datagent может быть **клиентом** этого интерфейса. Контракт принадлежит EDPortal. Это не API панели агентов (`/api`) и не вход в Datagent Cloud.

## Как передать токен

Заголовок `Authorization: Bearer <token>`. Токен создаётся в студии (`/api/v1/admin/agent/*` — это JWT методиста, не токен внешней системы), показывается **один раз**, в базе хранится только хеш.

Примеры ниже — **только подстановки**. Не вставляйте боевые JWT, секреты вебхуков, IP портала и идентификатор портала.

```http
Authorization: Bearer YOUR_EDPORTAL_AGENT_TOKEN
Idempotency-Key: YOUR_IDEMPOTENCY_KEY
X-Correlation-Id: YOUR_CORRELATION_ID
```

```bash
curl -s \
  -H "Authorization: Bearer YOUR_EDPORTAL_AGENT_TOKEN" \
  "https://YOUR_EDPORTAL_HOST/api/v1/agent/whoami"
```

Токены выдаются рабочим порталам, не демонстрационным. В журнале такой вызов пишется как `actorType=agent`.

На запись нужен заголовок `Idempotency-Key`: повтор с тем же телом возвращает тот же ответ, другое тело при том же ключе — ошибка 409. Заголовок `X-Correlation-Id` необязателен: он связывает ваш запрос с событием и не является номером запуска агента Datagent.

Лимиты по умолчанию: 10 чтений в секунду и 2 записи на токен. В ответе приходят `X-RateLimit-Remaining` и `X-RateLimit-Reset`.

## Что разрешено токену

| Право | Зачем |
| --- | --- |
| любой активный токен | `GET /whoami`, MCP `initialize` / `ping` / `tools/list` |
| `agent.read.users` | Пользователи и поиск |
| `agent.read.catalog` | Опубликованные курсы, тесты, программы, компетенции |
| `agent.read.analytics` | Сводки без персональных данных из ответов учеников |
| `agent.write.enrollments` | Назначить или отозвать обучение |
| `agent.write.content_draft` | Черновик правки. Опубликовать от имени токена нельзя — ответ 403 |
| `agent.notify` | Уведомление по шаблону |
| `agent.write.idp` | Черновик индивидуального плана развития (ИПР). Опубликовать от имени токена нельзя — ответ 403 |

## Какие запросы есть

Все пути ниже — относительно `/api/v1/agent`.

- `GET /whoami` — проверка токена, список прав, связь с Битрикс24
- `GET /users`, `POST /users/lookup` — сотрудники этого портала
- `GET /catalog/courses|tests|programs|competencies` — только опубликованное
- `GET /analytics/overview`, `GET /analytics/funnel` — сводки: назначено, сдано, не сдано, просрочено (`assigned` / `passed` / `failed` / `overdue`)
- `POST /enrollments`, `POST /enrollments/:id/revoke` — назначения. Крупный список уходит в proposal: его подтверждают в студии
- `GET /agent-proposals/:id` — статус такого предложения
- `POST /content/:entityType/:id/draft-patch` — черновик правки. Тип: `COURSE` / `LESSON` / `TEST` / `PROGRAM`
- `POST /notify`, `POST /idp/draft`

Опубликовать курс, тест или ИПР вызовом от имени токена **нельзя** (ответ 403). Черновик принимает методист в студии.

Тот же доступ есть через MCP: `POST /api/v1/agent/mcp`. Права и лимиты те же, инструменты называются `edp_*`.

## Какие события можно получать

Подписка по HTTPS: адрес (`https://YOUR_WEBHOOK_ENDPOINT`), секрет (`YOUR_WEBHOOK_HMAC_SECRET`) и список событий `learning.*`. Подпись приходит в заголовке `X-EDP-Signature`: HMAC SHA-256 от строки `{timestamp}.{body}`. Принимается только `https://`. Внутренние адреса отклоняются.

Примеры событий: назначение, просрочка, завершение курса, несданный тест, истечение сертификата, решение по proposal. Принимающая сторона отбрасывает повторы по `eventId`. Если событие породил ваш же вызов, обрабатывать его повторно не нужно: совпадут `correlationId` и `source=agent`.

## Чего этот адрес не делает

- Нет публичного API панели Datagent: задач, запусков и облачных агентов здесь нет.
- Нет обещания «полного REST Битрикс24» из этого документа.
- Нет записи в CRM портала через этот интерфейс.
