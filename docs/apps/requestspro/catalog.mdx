## Как устроен каталог

1. Администратор создаёт **группу** (типичные разделы: Кадры, Закупки, IT).
2. В группу добавляет **бизнес-процессы** из справочника портала.
3. Задаёт порядок групп и при необходимости иконку карточки.
4. Сотрудник в меню видит только группы, где есть доступные ему карточки.

Пустой каталог у администратора предлагает создать первую группу. У сотрудника без карточек — сообщение, что заявок нет, без кнопок админки.

## Откуда берутся процессы

Справочник читается из инфоблока типа **`bitrix_processes`**. Это процессы, которые уже настроены на портале. Заявки PRO их не проектирует и не заменяет роботами своего движка.

Нажатие по карточке открывает процесс портала (`/bizproc/processes/…`). Скоуп `bizproc` приложению не нужен: исполнение остаётся в Битрикс24.

## Справочники

При установке и по кнопке «Обновить справочники» подтягиваются отделы, сотрудники и процессы. Кэш отделов и сотрудников — около 30 минут, процессов — около 60 минут. Событие «добавлен сотрудник» не используется.

Иконку можно загрузить в приложение. Картинка процесса с Диска портала как файл не читается: скоуп `disk` не запрашивается.

## Чего в каталоге нет

- Нет конструктора маршрутов согласования вместо БП портала.
- Нет публичного REST «создать заявку в Заявки PRO».
- Нет выгрузки каталога на чужие порталы: данные привязаны к `member_id`.

Права на карточку — на странице [доступ](/docs/apps/requestspro/access).
