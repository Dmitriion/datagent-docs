## Кто считается администратором

Роль в приложении совпадает с **администратором портала Битрикс24**, не с правом «настройки приложений». Мутации каталога (группы, порядок, права, кэш, иконки) с клиента не принимаются: сервер проверяет пользователя через REST портала.

Сотрудник без этой роли не создаёт группы и не открывает редактирование. При попытке — отказ «недостаточно прав».

## Как считается видимость карточки

Администратор видит все карточки. Для остальных:

| Правило | Результат |
| --- | --- |
| Флаг «всем» (public) | Карточка видна |
| Список отделов и людей пуст | Карточка видна |
| Сотрудник в списке людей | Карточка видна |
| Отдел сотрудника в списке отделов | Карточка видна |
| Иначе | Карточка скрыта |

Права задаются на карточку процесса, не на группу целиком. Группа без видимых карточек сотруднику не показывается.

ФИО в интерфейсе берутся из `user_brief`, без контактных данных полного скоупа `user`.

## Где хранятся права

Коды хранилищ на портале: `rpro_groups` и `rpro_rights`. Это данные **портала клиента**, не общий каталог Datagent Cloud.

При удалении приложения с очисткой данных каталог на портале удаляется вместе с приложением. Кэш справочников на стороне приложения привязан к `member_id` и очищается при деинсталляции.

## Что настроить после установки

1. Создайте группы под процессы портала — см. [каталог](/docs/apps/requestspro/catalog).
2. Для каждой карточки укажите «всем» или списки отделов и сотрудников.
3. Проверьте вход под учёткой без прав администратора: лишних карточек быть не должно.
