# Память агента в Datagent — что запоминается и зачем

> **Зачем:** Чтобы агент **не начинал с нуля** каждый раз — помнил правила компании, прошлые выводы и факты по задаче. **Datagent** хранит память **отдельно от чата** и подключает её к запускам по правилам.

**Память** в Datagent — это не «история переписки в ChatGPT». Это **слои знаний** компании: что можно подмешивать агенту перед запуском и что записывать после успешного run.

## Это работает так

1. Администратор или менеджер открывает **Память** в настройках компании или агента.
2. Подключаются **слои** — например, рабочий контекст, справочник, записи после запусков.
3. Перед **запуском** агент получает релевантные фрагменты из разрешённых слоёв.
4. После run система может **сохранить** новые выводы (если включены хуки pre/post run).
5. Сервис **Gardener** со временем убирает устаревшее и помечает спорное на проверку.

Для оператора это выглядит так: агент в Битрикс24 отвечает с учётом «как мы принято формулировать» и прошлых договорённостей по компании — без ручной вставки простыни текста в каждый запрос.

## Что можно хранить

| Тип | Простыми словами |
| --- | --- |
| **Правила и политики** | Тон общения, запреты, шаблоны ответов |
| **Факты по компании** | Продукты, процессы, контакты — то, что редко меняется |
| **Контекст после run** | Выводы агента, которые стоит помнить в следующих задачах |
| **Справочник (wiki)** | Документация, которую агент может подтягивать в ответ |

Память **привязана к компании**: агент одной организации не видит слои другой.

:::tip Доступно бесплатно
Базовую память можно настроить на **Free**; объём и продвинутые политики зависят от тарифа и нагрузки.
:::

## Где настраивать в панели

1. Откройте **компанию** → раздел **Память** (или карточку **агента** → вкладка **Память**).
2. **Слои** — подключите нужные типы (рабочий, семантический, wiki и др.).
3. **Привязки** — укажите, какие слои использовать этому агенту.
4. **Админ** (для опытных) — заморозка записи, превью очистки Gardener, лимиты на «умный» отбор.

Если слои ещё не созданы, в панели есть действие **создать привязки по умолчанию** — стартовый набор для эксперимента.

## Заморозка и контроль

- **Заморозка** — временно запретить новые записи (аудит, инцидент, миграция).
- **Конфликты** — фрагменты, помеченные на проверку человеком.
- **Бюджет** — лимиты на дорогие операции отбора через нейросеть.

Это нужно руководителю автоматизации, не обязательно на первый день.

:::note Для инженеров
REST: `/api/companies/:id/memory/*`, `/api/agents/:id/memory/*`. Слои, chunks, bindings, gardener — в монорепо `doc/MEMORY-DOCS-INDEX.md`. Агент по API-ключу видит только свои слои.
:::

## Память и Битрикс24

Память **не заменяет CRM**. Сделки и контакты по-прежнему в **Битрикс24**. Datagent помнит **как агент должен работать** и **что уже выяснили в задачах** — удобно в паре с [GigaChat](../integrations/gigachat) и [каналами](../guides/06-channels).

## Частые вопросы

**Агент помнит всё навсегда?**  
Нет. Gardener и политики ограничивают объём и срок жизни записей.

**Можно ли стереть ошибочную запись?**  
Да, через интерфейс памяти и операции forget/correct (права администратора).

**Нужен ли программист для старта?**  
Нет — подключите слои по умолчанию и проверьте на одной задаче. Тонкая настройка — для команды автоматизации.

**Уходит ли память за рубеж?**  
Зависит от выбранной **языковой модели** и хостинга. Для российского контура используйте **GigaChat** / **YandexGPT**.
