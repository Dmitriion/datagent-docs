# Как Datagent следит за агентом во время работы

> **Зачем:** Чтобы агент **не пропал на полпути** — вы видите статус «выполняется», журнал шагов и можете **остановить** run. В **Datagent** за этим отвечает механизм **heartbeat** (пульс выполнения).

Пока агент работает, платформа ведёт **сеанс выполнения** (run): ставит в очередь, запускает модель и инструменты, пишет события в журнал. Это не «магия в фоне» — у каждого запуска есть id, статус и история.

## Это работает так

1. Вы (или Битрикс24) инициируете **запуск** — кнопка в панели или пробуждение агента.
2. Сервер создаёт запись run: **в очереди** → **выполняется** → **успех** или **ошибка**.
3. На каждом шаге в журнал попадают ответы модели и вызовы инструментов.
4. Если агент завис или вы нажали **Отмена** — run останавливается.
5. При согласовании run **ждёт** вашего решения и потом продолжается.

Для менеджера: открыли задачу → **Журнал запуска** → видно, что агент уже сделал и на чём остановился.

## Откуда стартует запуск

| Источник | Когда |
| --- | --- |
| **Панель** | Кнопка «Запустить» / «Пробудить» на задаче или агенте |
| **Битрикс24** | Новое сообщение клиента → задача → пробуждение агента |
| **Телеграм** | Входящее в задачу по правилам плагина |
| **Программный интерфейс** | Скрипт интеграции (`POST .../wakeup`) — для IT |

Каждый такой цикл — **отдельный** run со своим журналом. «Написать ещё раз в чат» ≠ новый прозрачный запуск; для учёта используйте **Запустить**.

## Что видно в журнале

- обращения к **GigaChat**, **YandexGPT** или другой модели;
- вызовы **инструментов** (таблица, браузер, уведомление);
- запросы **согласования**;
- финальный ответ или текст ошибки.

Статусы на русском в панели: в очереди, выполняется, успешно, ошибка, отменён.

:::tip Доступно бесплатно
Журнал запусков доступен на **Free** — это основа прозрачности продукта.
:::

## Надёжность и управление

- **Пауза / возобновление** агента — если нужно временно остановить все run.
- **Отмена** конкретного run — если пошло не туда.
- **Повторный запуск** — новая формулировка в задаче и снова «Запустить».

При интеграциях желательно передавать **ключ идемпотентности**, чтобы случайный двойной клик не создал два одинаковых run.

:::note Для инженеров
Запуск: `POST /api/agents/:id/wakeup`. Журнал: `GET /api/heartbeat-runs/:runId`, `/events`, `/log`. Сервис: `heartbeatService` в монорепо. Схема — [Как это работает](./how-it-works).
:::

## Heartbeat и кредиты

Каждый run **списывает кредиты** с кошелька, пока агент работает. Длинный run с браузером дороже короткого ответа. См. [Кредиты и тарифы](./credits).

## Частые вопросы

**Это то же самое, что cron?**  
Нет. Heartbeat — **один сеанс работы агента по задаче**, а не расписание на сервере. Расписание может *инициировать* wakeup, но журнал всё равно у run.

**Почему run «висит»?**  
Часто ждёт **согласования** или ответа от внешнего инструмента. Откройте журнал и раздел [Согласования](./approvals).

**Можно ли смотреть run в «Офисе»?**  
Да — на поле видно, кто **в работе** и кто **ждёт одобрения**. [Обзор «Офис»](../office/overview).

**Агент упал — что делать?**  
Прочитайте ошибку в журнале, поправьте задачу или настройки, запустите снова.
