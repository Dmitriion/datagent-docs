# Бюджеты и лимиты расхода

> **Зачем:** Не получить сюрприз в конце месяца — задать потолок расхода на компанию, агента или проект и остановить run при превышении.

**Бюджет** в Datagent — это **лимит расхода в деньгах** (хранится в копейках, `budgetMonthlyCents`), а не то же самое, что **кредиты** тарифа. Оба механизма работают параллельно.

## Бюджет и кредиты — в чём разница

| | **Кредиты / тариф** | **Бюджет (budget)** |
| --- | --- | --- |
| Что ограничивает | Подписка Free/PRO/Business: число агентов и run/мес | Расход **в рублях** (себестоимость run) на scope |
| Где смотреть | [Кредиты](./credits), кошелёк | Настройки компании / агента / проекта, отчёты costs |
| При исчерпании | Блок по тарифу или пустой кошелёк | **Hard-stop**: пауза агента/проекта, инцидент |
| Типичный вопрос | «Хватит ли 100 run на Free?» | «Не потратит ли один агент весь месячный лимит отдела?» |

Подробнее про кредиты и тарифы — [отдельная страница](./credits) и [тарифы облака](/docs/cloud/pricing).

## Это работает так

1. Задаёте **месячный лимит** для компании, конкретного **агента** или **проекта** (в панели или через API).
2. Платформа накапливает **cost events** по run (модель, tools, длительность).
3. При достижении порога срабатывает **политика** — чаще всего **hard-stop**: новые run блокируются.
4. Создаётся **бюджетный инцидент**; оператор разрешает его вручную после разбора.
5. Проект может перейти в **pause** с причиной `budget` — задачи проекта не стартуют, пока не снимете паузу.

:::info Учёт по месяцу UTC
По умолчанию лимит считается за календарный месяц UTC.
:::

## Где настраивать в панели

- **Компания** — общий потолок на организацию.
- **Карточка агента** — лимит на одну роль (например дорогой Claude только с потолком).
- **Проект** — лимит на направление — см. [проекты](./projects).

Сводка: раздел расходов / `GET /api/companies/:companyId/budgets/overview`.

## Инциденты

Когда лимит пробит, в панели появляется **budget incident**. Оператор с правами board:

1. Видит, какой scope (компания / агент / проект) сработал.
2. Решает: поднять лимит, остановить агента, сменить модель.
3. Закрывает инцидент через `POST …/budget-incidents/:id/resolve`.

До разрешения hard-stop может держать агента или проект на паузе.

## API (кратко)

| Маршрут | Действие |
| --- | --- |
| `GET …/budgets/overview` | Сводка политик и расхода |
| `PATCH …/companies/:id/budgets` | Лимит компании |
| `PATCH …/agents/:id/budgets` | Лимит агента |
| `POST …/budgets/policies` | Upsert политики (scope, amount, window) |
| `POST …/budget-incidents/:id/resolve` | Закрыть инцидент |

Детали полей — в `@datagent/shared` validators; обзор — [REST API](/docs/api-reference/overview).

## Практические советы

1. Начните с **одного агента-эксперимента** с низким лимитом — поймёте реальный расход за неделю.
2. Вынесите дорогие модели в отдельного агента с отдельным бюджетом.
3. Свяжите **проект** с лимитом, если отдел платит за себя.
4. Не отключайте согласования на рискованных tools — лишние run дороже, чем один approval.

## Частые вопросы

**Лимит 0 — что значит?**  
Часто «без отдельного потолка» или политика не задана — смотрите overview в панели.

**Кредиты есть, run не идёт?**  
Проверьте **бюджетный инцидент** и паузу проекта/агента, не только кошелёк.

**Где расход по моделям?**  
Отчёты costs в API и панели — by agent, by project, by model (для аналитики после пилота).
