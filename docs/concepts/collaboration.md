# Команда, приглашения и доступ

> **Зачем:** Подключить коллег к [app.datagent.ru](https://app.datagent.ru) с понятными правами — кто настраивает агентов, кто только запускает задачи, кто смотрит отчёты.

Datagent — **company-scoped**: каждый человек и каждый агент принадлежит организации. Доступ к данным другой компании закрыт на уровне API и панели.

## Роли людей в компании

| Роль | Обычно может |
| --- | --- |
| **owner** | Всё, включая биллинг и удаление компании |
| **admin** | Агенты, плагины, секреты, приглашения, бюджеты |
| **operator** | Задачи, run, согласования, просмотр агентов |
| **viewer** | Только чтение — без мутаций |

Точный набор прав задаётся **grants** в системе доступа; роль — удобная надстройка для типовых сценариев.

:::tip Viewer для руководителя
Дайте руководителю **viewer**, если он только проверяет журналы run — без риска случайно поменять агента.
:::

## Приглашения

**Приглашение (invite)** — ссылка вида `/invite/{token}` для входа в компанию без ручного создания учётки админом.

**Это работает так:**

1. **Admin** или **owner** создаёт приглашение в настройках компании (`POST /api/companies/:companyId/invites`).
2. Указывает тип (человек / агент), роль, срок действия, опционально onboarding-текст.
3. Отправляет ссылку коллеге.
4. Коллега проходит `/invite/…`, принимает условия — получает **membership** в компании.
5. Приглашение можно **отозвать** до принятия — `POST /api/invites/:inviteId/revoke`.

Полный список маршрутов — [доступ (API)](/docs/api-reference/access).

Публичная информация о приглашении (без авторизации): `GET /api/invites/:token` — название компании, тип, срок.

Первый вход в облаке — также [регистрация](/docs/cloud/getting-started) и мастер компании; invite — для **второго и следующих** участников.

## Участники компании

- Список: `GET /api/companies/:companyId/members`
- Изменение роли / статуса — через API доступа (board).
- Удаление участника — с проверкой иерархии ролей (нельзя удалить равного или старшего без прав).

Агенты в оргструктуре — отдельные сущности; люди и агенты не смешиваются в одной таблице «сотрудников».

## Оргструктура агентов

Визуальная **оргкарта** AI-сотрудников:

- `GET /api/companies/:companyId/org` — JSON-дерево
- `GET …/org.svg` / `…/org.png` — картинка для отчётов

Полезно для демо руководству: кто кому подчиняется, какие роли в [Офисе](/docs/office/overview).

## Агенты и API-ключи

- **Ключ агента** — только свой профиль, wakeup, ограниченный inbox, **не** чужие секреты и компании.
- **Сессия панели** — полный board-контекст в рамках роли человека.

Подробнее о ключах — [справка по агентам (API)](/docs/api-reference/agents).

## Согласования и inbox

Оператор с ролью **operator** видит [inbox](./inbox) и [согласования](./approvals). **Viewer** — только просмотр карточек без approve.

## Частые вопросы

**Ссылка invite истекла?**  
Создайте новое приглашение; старые токены имеют `expiresAt`.

**Коллега видит чужую компанию?**  
Нет — membership привязан к одной организации; переключение компании в панели, если у человека несколько.

**Кто может приглашать?**  
Обычно **admin** / **owner** с правом `users:invite`.
