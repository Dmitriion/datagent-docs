# Секреты компании

> **Зачем:** Хранить ключи GigaChat, Yandex Cloud и интеграций **вне** текста задач и system prompt — с ротацией и аудитом.

**Секрет** в Datagent — зашифрованное значение (API-ключ, JSON сервисного аккаунта, токен), на которое ссылаются агенты и плагины через **secret_ref**. Оператор видит имя и метаданные, не сам ключ в открытом виде.

## Это работает так

1. Администратор открывает **Настройки компании → Секреты** на [app.datagent.ru](https://app.datagent.ru).
2. Создаёт секрет — имя, тип, значение (один раз при создании или импорт).
3. В форме **агента** или **плагина** выбирает ссылку на секрет вместо вставки ключа в поле.
4. Перед run сервер **подставляет** значение в окружение адаптера (например `GIGACHAT_ACCESS_TOKEN`, `YANDEX_SA_KEY_JSON`).
5. При ротации обновляете секрет — агенты подхватят новое значение без правки prompt.

:::warning Не кладите ключи в задачу
Ключи в описании задачи или prompt попадут в журнал run — храните их в секретах.
:::

## Типичные секреты

| Секрет | Зачем |
| --- | --- |
| **GigaChat** | OAuth Сбера — client id/secret; токен кэшируется платформой |
| **YandexGPT** | JSON ключа сервисного аккаунта + `folderId` в конфиге агента |
| **Плагины** | Webhook Битрикс24, токены ботов, ключи внешних API |
| **BrowserBridge** | Параметры подключения локальной службы |

Инструкции по провайдерам: [GigaChat](/docs/integrations/gigachat), [YandexGPT](/docs/integrations/yandexgpt).

## Провайдеры и импорт

Компания может настроить **провайдер секретов** (встроенное хранилище Datagent или внешний — в enterprise-сценариях). В облаке по умолчанию достаточно встроенного vault.

Доступны **импорт** и **ротация** (`POST …/secrets/:id/rotate`), журнал **access-events** — кто и когда читал секрет.

:::tip С первой недели
В [учебнике «Команда агентов»](/docs/guides/02-your-team) есть шаг про secret_ref — полезная привычка сразу.
:::

## Кто может управлять

Только **оператор панели** (board) с доступом к компании. Агент по API-ключу **не** читает список секретов — только получает уже разрешённые значения в runtime своего run.

## Частые вопросы

**Секрет пропал из формы агента?**  
Проверьте, что секрет не удалён и привязка env binding на месте; пересохраните агента.

**Нужен ли секрет на Free?**  
Да, если используете GigaChat/Yandex — ключи провайдера обязательны; храните их как секреты, не в репозитории.

**Это то же самое, что API-ключ агента?**  
Нет. **Ключ агента** — для вызова API Datagent. **Секрет** — для вызова GigaChat, CRM и т.д. изнутри run.
