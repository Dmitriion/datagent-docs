# Настройки компании

> **Зачем:** Один раз настроить **организацию** в [app.datagent.ru](https://app.datagent.ru) — имя, доступ коллег, плагины, секреты и лимиты — чтобы агенты работали в правильном контуре.

**Компания** — изолированный tenant: свои агенты, задачи, память, артефакты и биллинг. Настройки доступны **owner** и **admin**; оператор видит только то, что нужно для работы.

## Где в панели

| Раздел | Что настраиваете |
| --- | --- |
| **Настройки компании** | Название, префикс в URL, брендинг |
| **Команда** | Приглашения, роли — [команда и доступ](./collaboration) |
| **Менеджер плагинов** | Установка и включение интеграций — [плагины](/docs/cloud/plugins) |
| **Секреты** | Ключи API, токены ботов — [секреты](./secrets) |
| **Навыки** | Каталог company skills — [навыки](/docs/cloud/skills) |
| **Бюджеты** | Лимиты проектов и агентов — [бюджеты](./budgets) |
| **Экспериментальные** | Флаги вроде «Офис» (если доступны в instance) |

Первичный мастер после регистрации — в [быстром старте](/docs/cloud/getting-started); эта страница — для **повседневной** администрации.

## Профиль и URL

- **Название** — отображается в панели и приглашениях.
- **Префикс** (`issuePrefix`) — короткий код в адресе: `https://app.datagent.ru/TES/...` для компании с префиксом `TES`.
- **Брендинг** — логотип и цвета на странице invite (если включено).

Изменение префикса ломает закладки — согласуйте с командой перед сменой.

## Онбординг новых участников

1. **Admin** создаёт [приглашение](./collaboration) с ролью `operator` / `viewer` / `admin`.
2. Коллега переходит `/invite/{token}` — видит название компании и текст онбординга.
3. После принятия — переключение компании в шапке, если у человека несколько организаций.

Первый владелец создаётся при регистрации — [аккаунт](/docs/cloud/account).

## Плагины и интеграции

Установка **на уровне instance** (глобально) и включение **для компании**:

1. Менеджер плагинов → **Установить** пакет.
2. **Включить** для компании и заполнить **config** (webhook Bitrix24, bot Telegram и т.д.).
3. Привязать агента к каналу по инструкции интеграции.

Каналы CRM и мессенджеров — [каналы](./channels). API установки — [плагины (API)](/docs/api-reference/plugins).

## Секреты и адаптеры

Секреты компании (`GIGACHAT_*`, `YANDEX_*`, токены ботов) хранятся **отдельно** от кода плагина. Агент получает их только на время run через bindings — см. [секреты](./secrets) и [GigaChat](/docs/integrations/gigachat).

## Экспериментальные возможности

Часть UI за флагами instance (например **«Офис»** — `enableOffice`). Включение — в экспериментальных настройках компании; без флага пункт меню не появится — [обзор Офиса](/docs/office/overview).

:::info Не для всех тарифов
BrowserBridge и расширенные плагины могут требовать **PRO** — [тарифы](/docs/cloud/pricing).
:::

## Экспорт и перенос (редко)

API `POST /api/companies/:companyId/export` и импорт — для переноса между instance (часто **Enterprise**). В облаке `app.datagent.ru` обычно достаточно приглашений; полный runbook переноса — в планах справки P3.

## Частые вопросы

**Кто может менять секреты?**  
Обычно **admin** / **owner**; оператор не видит значения секретов.

**Где лимит агентов?**  
На тарифе **Free** — 3 агента; детали — [кредиты](./credits) и [тарифы](/docs/cloud/pricing).

**Как включить Офис?**  
Экспериментальные настройки компании + флаг на instance; затем маршрут `/{prefix}/office`.
