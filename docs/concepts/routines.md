# Регламенты

Утренний дайджест, проверка входящих каждые два часа, ночная выгрузка из CRM — не нажимать **Запустить** вручную каждый раз. **Регламент** в Datagent задаёт **расписание**: в нужное время платформа запускает агента с тем же поручением, что вы описали один раз.

Регламент отвечает на *когда*. *Что произошло* — в [журнале запуска](./heartbeat).

## Это работает так

1. **Откройте раздел «Регламенты»** в панели компании на [app.datagent.ru](https://app.datagent.ru).
2. **Создайте регламент** — название, агент-исполнитель, шаблон задачи или текст поручения.
3. **Добавьте расписание** — например, «каждый будний день в 09:00» или кнопку «Запустить сейчас».
4. **Включите регламент** — по расписанию платформа запускает агента так же, как при ручном «Запустить».
5. **Смотрите результат** в задачах и журнале запуска.

Регламент отвечает на вопрос *когда* стартовать. *Что произошло внутри* — в [журнале запуска](./heartbeat).

## Где настраивать в панели

| Шаг | Действие |
| --- | --- |
| 1 | **Компания** → **Регламенты** → **Новый регламент** |
| 2 | Выберите **агента** и опишите работу (что он должен делать каждый раз) |
| 3 | Вкладка **Триггеры** — расписание или ручной запуск |
| 4 | При необходимости укажите **проект** — задачи попадут в нужный портфель |

Создавать и менять регламенты могут операторы с правом назначать задачи. Агент по API-ключу управляет только **своими** регламентами.

Часовой пояс берётся из настроек экземпляра — учитывайте это, если команда в разных регионах.

## Типовые сценарии

- **Утренний отчёт** — агент-аналитик, пн–пт 08:30, задача «Сводка за вчера».
- **Проверка входящих** — агент поддержки, каждые 2 часа, список новых обращений.
- **Синхронизация CRM** — после [Битрикс24](/docs/integrations/bitrix24) (тариф **Studio+**), ночной запуск без участия менеджера.

:::warning[Лимит запусков]
Каждый срабатывание регламента — один **запуск агента** в месячной квоте. На **Free** (100 в месяц) плотное расписание быстро исчерпает лимит — см. [Запуски и лимиты](./credits).
:::

## Если что-то пошло не так

- **Пауза регламента** — выключите переключатель «активен»; расписание перестанет стартовать запуски.
- **Бюджетный стоп** — при превышении [бюджета](./budgets) проекта или компании новые запуски могут блокироваться до разбора инцидента.
- **История изменений** — в ревизиях регламента видно, кто поменял расписание.

## Частые вопросы

**Регламент создаёт новую задачу каждый раз?**  
Зависит от шаблона: часто — новая задача на каждый запуск или одна открытая «канальная» задача. Уточните в форме регламента.

**Можно без расписания?**  
Да — кнопка «Запустить сейчас» в карточке регламента.

<details>
<summary>Для разработчиков</summary>

API: `GET/POST /api/companies/:companyId/routines`. Ручной запуск: `POST` на endpoint регламента. Webhook-триггеры — с секретом ротации через API.

</details>
