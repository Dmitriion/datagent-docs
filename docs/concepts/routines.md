# Рутины

> **Зачем:** Чтобы агент делал одно и то же **по расписанию** — утренний дайджест, проверка inbox, синхронизация CRM — без вашего «Запустить» каждый день.

**Рутина (routine)** — правило автоматизации: в заданное время Datagent **пробуждает агента** и создаёт или обновляет работу по шаблону. Вы настраиваете это в панели компании на [app.datagent.ru](https://app.datagent.ru).

## Это работает так

1. Создаёте рутину — название, **агент-исполнитель**, шаблон задачи или payload.
2. Добавляете **триггер** — расписание (cron) или ручной запуск.
3. Включаете рутину (**active**); по cron сервер вызывает тот же механизм, что и **Wakeup**.
4. Смотрите результат в задачах и журнале run — как при ручном запуске.

:::info Рутина и heartbeat
**Routine** — когда стартовать работу по расписанию. **Heartbeat** — как выполняется уже запущенный run. **Wakeup** — разовый старт вручную или по API.
:::

## Где настраивать

Раздел **Рутины** в настройках компании (или API `GET/POST /api/companies/:companyId/routines`). Можно привязать рутину к **проекту** — тогда задачи попадают в нужный портфель.

Права: создавать и менять чужие рутины может оператор с правом назначать задачи; агент по API-ключу — только **свои** рутины.

## Триггеры и расписание

| Тип | Для чего |
| --- | --- |
| **Cron** | «Каждый будний день в 09:00» — классический дайджест |
| **Ручной run** | Кнопка «Запустить сейчас» или `POST` на endpoint рутины |
| **Секрет триггера** | Для внешних webhook — ротация через API |

Часовой пояс берётся из настроек **instance** — учитывайте это, если команда в нескольких регионах.

## Типовые сценарии

- **Утренний отчёт** — агент-аналитик, cron пн–пт 08:30, задача «Сводка за вчера».
- **Проверка inbox** — агент поддержки, каждые 2 часа, краткий список новых обращений.
- **Синхронизация CRM** — после установки [Битрикс24](/docs/integrations/bitrix24), ночной run без участия менеджера.

:::warning Рутина съедает кредиты
Каждый запуск routine — это run. На **Free** (100 run/мес) плотное расписание быстро исчерпает лимит — см. [кредиты](./credits).
:::

## Что происходит при сбое

- Рутину можно перевести в паузу (**не active**) — cron перестанет стартовать run.
- Если сработал **бюджетный hard-stop** у компании, агента или проекта — новые run могут блокироваться до снятия инцидента — см. [бюджеты](./budgets).
- История изменений рутины хранится в **ревизиях** — удобно для аудита «кто поменил расписание».

## Частые вопросы

**Рутина создаёт новую задачу каждый раз?**  
Зависит от настроек шаблона. Частый паттерн — одна открытая задача-«канал» или новая задача на каждый run; уточните в форме рутины.

**Можно ли рутину без cron?**  
Да — ручной запуск и интеграции через API; cron необязателен.

**Агент сам создаст рутину?**  
Агент с API-ключом может управлять рутинами **только на себя**; назначить другого исполнителя может оператор панели.
