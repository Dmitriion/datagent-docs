# Runs — как агент расходует ресурсы

Каждый раз, когда агент выполняет задачу, — тратится один **run** (запуск агента). Runs обновляются в начале каждого расчётного месяца. Закончились — новые запуски не стартуют до следующего месяца или до смены тарифа.

Это лимит **платформы** на [app.datagent.ru](https://app.datagent.ru), а не оплата токенов GigaChat или YandexGPT — ключи провайдера вы подключаете отдельно.

**Например:** агент собрал отчёт по продажам за неделю из Битрикс24 — это один run. Пять таких отчётов в день — уже десятки runs к концу месяца.

## Сколько runs на каком тарифе

| Тариф | Runs в месяц | Агентов |
| --- | --- | --- |
| **Free** | 100 | 3 |
| **Solo** | 1 000 | без ограничения |
| **Studio** | 8 000 | без ограничения |
| **Business** | 50 000 | без ограничения |
| **Enterprise** | по договору | по договору |

Полная таблица цен и возможностей — [Тарифы облачной версии](../cloud/pricing).

## Что считается run

Агент получил задачу, прошёл цикл работы — модель, инструменты, ответ — и вернул результат. Нажали «Запустить», сработал [регламент](./routines) по расписанию или агент снова взял задачу после [пульса](./heartbeat) — обычно это один run.

## Что происходит, когда runs заканчиваются

Агент получает новую задачу, но **не запускает** её. В панели появляется уведомление. Незавершённые задачи не теряются — их можно запустить снова, когда лимит обновится или вы перейдёте на тариф выше.

| Тариф | При приближении к лимиту | Когда runs закончились |
| --- | --- | --- |
| **Free** | Уведомление | Новые запуски не стартуют до смены тарифа |
| **Solo** | Уведомление | Новые запуски не стартуют; предложение перейти на Studio |
| **Studio**, **Business** | Уведомление | Новые запуски не стартуют; на Studio и Business планируется докупка пакетов — см. [тарифы](../cloud/pricing) |

Отдельно от runs действуют **бюджеты** в рублях на компанию, агента или проект — при превышении агент тоже останавливается. Подробнее: [Бюджеты](./budgets).

Чтобы не останавливать работу — перейдите на тариф выше или дождитесь обновления лимита в начале месяца.

## Как не упереться в лимит раньше времени

1. Сверьте тариф с числом runs за неделю — отчёт в панели и [тарифы](../cloud/pricing).
2. Включите [согласования](./approvals) на рискованных шагах — меньше лишних запусков на откатах.
3. Разнесите дорогие модели по отдельным агентам с [бюджетом](./budgets).
