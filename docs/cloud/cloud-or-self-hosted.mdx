# Cloud или свой контур: как выбрать Datagent

Datagent можно запустить двумя способами: **Cloud** на [app.datagent.ru](https://app.datagent.ru) — в браузере без своего сервера — или **развёртывание в своём контуре** по тарифу **Корпоративный**, когда данные и инфраструктура остаются у вас. Ниже — критерии выбора, а не реклама одного варианта.

## Если коротко

- Cloud — быстрый старт: регистрация, компания, агент и задача в браузере.
- Свой контур нужен, когда данные должны оставаться у вас. Это тариф Корпоративный.
- Роли, 1С и установка на своих серверах входят в тариф Корпоративный. Это проект внедрения, не самостоятельная установка.
- В публичной справке нет пошаговой «скачал и поставил» инструкции для боевого контура — внедрение идёт через sales.

## Когда подходит Cloud

- Нужен результат в панели, а не администрирование инфраструктуры.
- Команда готова хранить рабочие данные Datagent на инфраструктуре сервиса в РФ.
- Хотите проверить сценарии на бесплатном тарифе. Готовые коннекторы не входят в бесплатный тариф. Доступно на платных условиях, [уточните у нас](https://datagent.ru/#demo).

Путь: [обзор Cloud](/docs/cloud) → [старт](/docs/cloud/getting-started) → [регистрация](https://app.datagent.ru/signup).

## Когда подходит свой контур

- Данные и доступ должны оставаться в периметре компании.
- Нужны внутренние системы, единый вход и условия ИБ, закреплённые в договоре.
- Готовы к проекту внедрения с командой Datagent, а не к самостоятельной установке «за вечер».

Путь: [свой контур](/docs/cloud/on-premise) → заявка на [sales@datagent.ru](mailto:sales@datagent.ru).

## Сравнение

| | Cloud | Свой контур (Корпоративный) |
| --- | --- | --- |
| Где данные | У Datagent, в РФ | На вашем оборудовании |
| Как начать | Регистрация в браузере | Заявка и проект внедрения |
| Тариф | Бесплатный | Корпоративный, по договору |
| Поддержка | По тарифу облака | Сопровождение внедрения и эксплуатации |
| Ответственность за инфраструктуру | Datagent | Заказчик + условия договора |

## Как это работает на практике

1. Сформулируйте ограничение: «можно ли хранить рабочие данные агентов у провайдера» или «только у нас».
2. Если можно у провайдера — начните с Cloud и пилота сценария.
3. Если данные только у вас, опишите требования ИБ и число пользователей в заявке на тариф Корпоративный.
4. Облако не заменяет установку в своём контуре. Свой контур: тариф Корпоративный.

## Пример

Команда продаж хочет сводки из CRM на этой неделе — достаточно Cloud и тарифа с нужными коннекторами. Финтех с политикой «данные не покидают периметр» — обсуждает свой контур через sales, а не ставит сервер из открытого репозитория без договора.

## Что потребуется

- Для Cloud: браузер, аккаунт, ключи модели (GigaChat / YandexGPT и др.).
- Для своего контура: контакт ИБ/ИТ, оценка числа пользователей и агентов, желаемый срок пилота.

## Ограничения

- Публичная документация **не** содержит полной инструкции промышленной установки.
- Не обещаем конкретные SLA, сертификаты и сроки внедрения вне договора.
- Выбор модели и ключей LLM в обоих случаях остаётся за вами.
