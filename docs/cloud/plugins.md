# Плагины и расширения Datagent — для пользователей и разработчиков

> **Зачем:** Расширить **Datagent** без ожидания новой версии продукта — подключить **Битрикс24**, **Телеграм**, браузер, таблицы. Для команды разработки — собрать **свой** плагин и поставить в облако через **менеджер плагинов** на [app.datagent.ru](https://app.datagent.ru).

**Плагин** — отдельный модуль с фоновым процессом: мост в CRM, инструменты агента, страница настроек в панели. Это **не** замена **GigaChat** — модель подключается [отдельно](../integrations/gigachat).

## Это работает так (для пользователя)

1. Администратор открывает **Менеджер плагинов** в панели.
2. Выбирает плагин (например **Битрикс24**) → **Установить** для компании.
3. Заполняет настройки на странице плагина (webhook, бот, ключи).
4. Включает плагин для **агентов** / задач по инструкции.
5. Агент на **GigaChat** начинает использовать новые возможности (чаты, tools).

Установка **без кода** — типичный путь для **Битрикс24** и **Телеграм**.

## Навыки (skills) и плагины

**Навыки** — готовые инструкции и чеклисты для агентов (каталог в разделе **Навыки** компании). Часть навыков **автоматически предлагает** включить нужный плагин — например для Excel.

| | **Плагин** | **Навык** |
| --- | --- | --- |
| Что это | Код + worker + интеграция | Сценарий и тексты для агента |
| Кто ставит | Админ в менеджере плагинов | Менеджер в каталоге навыков |

Подробнее: [Первый агент — каталог навыков](../cloud/first-agent#каталог-навыков-необязательно).

## Для разработчиков плагинов

Если встроенных интеграций мало — можно написать **свой** плагин.

### Это работает так

1. Создаёте npm-пакет с **манифестом** и **worker** (Plugin SDK).
2. Публикуете пакет или передаёте `.tgz` команде Datagent.
3. Устанавливаете через **менеджер плагинов** (URL npm или file).
4. Worker стартует на стороне instance; агент вызывает ваши **tools**.

Пошагово с кодом: [Создание плагина](../tutorials/build-plugin).

### Scaffold

```bash
npx @datagent/create-datagent-plugin @my-org/datagent-demo-greeter \
  --template connector \
  --display-name "Учебный плагин-приветствие"
```

### Публикация в каталог

Публичный **маркетплейс плагинов** с самообслуживанием для сторонних авторов — **в разработке**. Сейчас:

- встроенные плагины поставляются с продуктом;
- кастомные — установка через менеджер плагинов по согласованию с администратором instance;
- вопросы по листингу и партнёрству — **[sales@datagent.ru](mailto:sales@datagent.ru?subject=Плагин%20для%20Datagent)**.

Мы **не** обещаем здесь фиксированный процент от выручки — условия для авторов обсуждаются отдельно.

:::note Для инженеров

Архитектура: `PluginWorkerManager`, JSON-RPC stdio, `POST /api/plugins/tools/execute`. Идентификатор — `manifest.id` (например `datagent.bitrix24`). См. [архитектуру](../concepts/agent-architecture), [API](../api-reference/overview).

:::

## Частые вопросы

**Нужен ли программист для Битрикс24?**  
Часто достаточно админа CRM + ответственного за Datagent. Сложные сценарии — с разработчиком.

**Плагин = адаптер GigaChat?**  
**Нет.** Адаптер — **модель**; плагин — **действия** (CRM, файлы, браузер).

**Можно ли один плагин на Free?**  
Да, базовые интеграции доступны на Free; **BrowserBridge** — только **PRO**.

**Где взять исходники встроенных плагинов?**  
Open-core на [GitHub](https://github.com/Dmitriion/datagent) в `packages/plugins/`.
