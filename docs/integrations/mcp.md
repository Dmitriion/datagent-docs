# Внешние инструменты для агента (MCP)

:::info[Studio и выше]
Реестр внешних подключений доступен на тарифах **Studio** и выше (как и большинство коннекторов компании). [Тарифы →](../cloud/pricing)
:::

:::warning[Только для Cursor-агентов]
Внешние подключения MCP работают с агентами на адаптере **Cursor**. GigaChat, YandexGPT и другие адаптеры не получают эти инструменты через данный реестр.
:::

**MCP** — способ подключить к ИИ-исполнителю **внешние инструменты и данные**: справочники, документацию, корпоративные сервисы, специализированные API. Сначала вы добавляете подключение в панели Datagent, затем разрешаете его нужному Cursor-агенту.

Расшифровка для любопытных: MCP — *Model Context Protocol*, общий язык, на котором агент и внешний сервис договариваются о доступных действиях.

## Три разных «MCP» в Datagent — не путайте

| Что | Для кого | Зачем |
| --- | --- | --- |
| **Реестр внешних MCP** (эта страница) | Оператор / админ компании | Подключить Context7, Bitrix MCP, свой HTTP-сервис к Cursor-агентам |
| **[1С Коннектор](./1c-connector)** | Business+, админ 1С | Отдельный мост к учётной базе 1С |
| **MCP-сервер Datagent** | Разработчики | Доступ к API Datagent из внешних IDE — не этот раздел |

Ниже — только **реестр внешних MCP** в панели.

## Когда это нужно

- Агенту нужны данные или действия из внешней системы **по HTTP**
- Вы хотите один раз настроить подключение для компании и выдавать его агентам по списку
- Разработчик уже поднял MCP-сервер, а оператору нужно «включить» его в Datagent без правки файлов на машине агента

## Пример

Команда добавила MCP с документацией библиотек. Cursor-агент в задаче «Проверь, как вызвать API X» обращается к этому подключению и приводит актуальные примеры — без копирования документации вручную.

## Как подключить

1. Убедитесь, что тариф компании **Studio** или выше.
2. [app.datagent.ru](https://app.datagent.ru) → **Менеджер плагинов** → включите плагин **MCP**.
3. Откройте страницу **MCP** компании (или вкладку интеграций MCP).
4. Добавьте подключение: понятное имя, адрес сервиса, способ входа (без входа / токен / авторизация по ссылке).
5. Нажмите **Проверить** — дождитесь статуса «в сети» и списка доступных инструментов.
6. В карточке **Cursor-агента** разрешите это подключение в группе инструментов MCP. **Имя в политике агента должно совпасть** с именем подключения.
7. Создайте короткую тестовую задачу и попросите агента вызвать инструмент из списка.

## Состояния подключения

| Статус | Что значит |
| --- | --- |
| В сети | Проверка прошла, инструменты доступны |
| Нужна авторизация | Нет токена или требуется вход по ссылке |
| Недоступен | Сервис не отвечает или таймаут |
| Выключено | Подключение отключено в настройках |
| Не настроено | Нет адреса |

:::tip[Важно]
Зелёный статус в настройках **не всегда** равен успеху в старой сессии агента. Если агент «не видит» инструмент — запустите **новую** задачу после изменения настроек.
:::

## Ограничения

- Секреты и токены храните в **секретах компании**, не в тексте задачи.
- Не обещайте доступ «любому агенту сразу» — только тем, кому выдали разрешение.
- 1С подключается отдельно через [1С Коннектор](./1c-connector), даже если там тоже используется MCP-протокол.

## Частые вопросы

**Нужен программист?**  
Для добавления готового HTTP-адреса — часто нет. Для поднятия собственного MCP-сервиса — да.

**Это то же, что BrowserBridge?**  
Нет. [BrowserBridge](./browserbridge) управляет **вашим браузером**. MCP подключает **внешние инструменты по адресу**.

**Связано с 1С?**  
Да по идее «внешние данные», но в продукте это **разные** страницы: [1С](./1c-connector) и этот реестр.
