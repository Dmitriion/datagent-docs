# Datagent против Make: что выбрать для автоматизации российских сервисов

## Главное отличие одной строкой

Make (ex-Integromat) — визуальный конструктор сценариев. Datagent — ИИ-агент, который сам выбирает, какие данные запросить, и отвечает в контексте вашей компании.

## Сравнение по ключевым критериям

| Критерий | Datagent | Make |
| --- | --- | --- |
| МойСклад | ✅ **211** инструментов (чтение) | ⚠️ уточните — часто через HTTP |
| Wildberries | ✅ **165** инструментов | ⚠️ уточните / HTTP |
| Ozon | ✅ **105** инструментов | ⚠️ уточните / HTTP |
| Авито | ✅ **104** инструмента | ⚠️ уточните / HTTP |
| Яндекс 360 | ✅ **36** инструментов | ⚠️ уточните |
| ИИ-агент (думает сам) | ✅ задача + инструменты сервисов | ⚠️ сценарии; AI-модули — отдельная модель |
| Работа в России | ✅ продукт под РФ-сервисы | ⚠️ ограничения оплаты/доступа возможны |
| Бесплатный план | ✅ Free / Solo с лимитами | ⚠️ лимиты операций на free |
| Глубина маркетплейсов | ✅ десятки–сотни read-инструментов | ⚠️ зависит от кастомной сборки |

Make силён в сложных ветвлениях и визуальных сценариях. Для МойСклад / WB / Ozon / Авито готового «глубокого» модуля в публичном каталоге обычно нет — типичный путь: HTTP и ручная карта полей.

## Когда выбрать Datagent

- Нужна **автоматизация бизнеса без Zapier/Make-мышления**: спросили агента → получили ответ по API
- Селлер или учёт на **МойСклад + маркетплейсы** — и важна глубина чтения (заказы, аналитика, финансы)
- Хотите **контроль доступов** (какому агенту что видно) и режим только чтения
- Команда в РФ и не хочет собирать каждый метод Seller API вручную

## Когда Make подойдёт лучше

- Нужен **визуальный сценарий** с десятками шагов, фильтрами и ветками без «рассуждающего» агента
- Основной стек — западные SaaS, уже описанные модулями Make
- Есть интегратор, который готов поддерживать HTTP-сценарии к российским API
