# SEO Operations Runbook (внутренний)

**Не публиковать.** Файл исключён из docs plugin (`exclude`) и sitemap (`ignorePatterns`).

Назначение: операционный план подключения **Яндекс.Вебмастера** и работы с органикой docs.datagent.ru.

**Политика измерения (РФ, 2026):** Google Search Console / `GOOGLE_SITE_VERIFICATION` / GA / GTM **не используем**. Единственный SEO-webmaster tooling — Яндекс.Вебмастер (+ уже подключённая Яндекс.Метрика на docs, без расширения без решения владельца).

---

## День 0 — подключение измерения

1. **Яндекс.Вебмастер**
   - Добавить сайт `https://docs.datagent.ru`.
   - Meta-тег: значение `content` → env `YANDEX_VERIFICATION` (не коммитить в Git).
   - Пересобрать и задеплоить docs → подтвердить владение.
2. **Sitemap**
   - Индексирование → Файлы Sitemap → `https://docs.datagent.ru/sitemap.xml`
3. **robots.txt** — открыть `https://docs.datagent.ru/robots.txt`: Sitemap указан; политика crawlers без изменений (`GPTBot` disallow; search/answer bots allow).
4. **Переобход** — главная + 5 ключевых URL:
   - `/`
   - `/docs/intro`
   - `/docs/cloud`
   - `/docs/integrations/overview`
   - `/docs/cloud/cloud-or-self-hosted`
5. **Доступы** — владелец проекта как Owner; SEO/маркетинг — по политике Вебмастера.
6. **HTTPS** — сертификат валиден, без mixed content на ключевых страницах.

### Где взять токен и куда положить

| Сервис | Где взять | Env var | Куда |
|--------|-----------|---------|------|
| Яндекс.Вебмастер | Настройки → Подтверждение прав → Meta-тег | `YANDEX_VERIFICATION` | CI/hosting secrets; локально `.env.local` (в `.gitignore`) |

Шаблон: `.env.example`. Пустые значения **не** должны попадать в HTML как пустые `<meta>`.

**Не подключать:** Google Site Verification, Search Console, GA, GTM. Метрику на docs не расширять без запроса владельца.

## Первые 30 дней (только Яндекс)

| Действие | Где в Вебмастере |
|----------|------------------|
| Индексирование | Индексирование → страницы |
| 404 / soft 404 | Исключённые страницы; ручной переобход |
| Показы без кликов | Поисковые запросы → CTR |
| Позиции 8–30 | Запросы → позиции |
| Запросы по интеграциям | фильтр по запросам / страницам |
| Каннибализация | один query → разные URL |
| Crawl errors | Переобход / диагностика роботов |

Правило: **не** менять title/H1 ключевых страниц чаще раза в 2–3 недели без данных.

## 60–90 дней

1. Обновить семантическое ядро фактами из **Яндекс.Вебмастера** (и Wordstat при необходимости) — не гипотезами и не данными GSC.
2. Выбрать следующие ≤3 страницы из `SEO-CONTENT-BACKLOG.md` по фактическому спросу.
3. Доработать страницы с показами и слабым CTR (title/description, intro).
4. Доработать страницы с кликами, но слабым переходом к product action (CTA, внутренние ссылки).
5. Решить: нужны ли отдельные OG PNG для 5 pillars.
6. Решить: нужна ли аналитика docs → signup (отдельное решение владельца; без Google Analytics).

## KPI (без числовых целей до baseline)

| Метрика | Где смотреть | Почему важна | Целевое действие |
|---------|--------------|--------------|------------------|
| Проиндексированные страницы | Яндекс → Индексирование | База охвата | Исправить исключённые / ошибки crawl |
| Показы по docs | Поисковые запросы | Видимость | Не трогать URLs; усиливать title при низком CTR |
| CTR топ-страниц | Поисковые запросы | Релевантность сниппета | Править description/title по данным |
| Запросы по интеграциям | фильтр query | Коммерческий intent | Перелинковка на integration + guide |
| Клики → signup (если появится аналитика) | Метрика / позже | Product action | CTA и путь Cloud |
| 404 / soft 404 | Исключённые / переобход | Потери crawl budget | Redirect или контент |
| Каннибализация | один query → N URL | Размытие позиций | Склеить intent / canonical / links |

Baseline: зафиксировать цифры на **день 7** и **день 30** после подтверждения домена в Вебмастере. Целевые % не ставить до этого.
